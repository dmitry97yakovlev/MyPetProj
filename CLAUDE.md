# MyPetProj — трекер привычек с геймификацией

Этот файл фиксирует принятые архитектурные решения по проекту. Все блокирующие вопросы закрыты (см. раздел 8) — можно смотреть как на источник правды при написании кода.

## 1. Идея

Трекер привычек/саморазвития в духе **SuperBetter**, но проще. Личностный рост оформлен как игра:

```
Эпическая победа (Epic Win)   — большая долгосрочная цель, напр. «Привести себя в форму»
  └─ Квесты (Quests)          — под-цели внутри Epic Win, напр. «Пробежать 5 км»
       └─ Ежедневные задачи   — повторяющиеся действия, напр. «Пробежать 2 км сегодня»
```

- У Epic Win / квестов / задач — **таймлайн и дедлайны**.
- Пользователь может **создавать свои квесты и ежедневные задачи** (не только пресеты) — нужен гибкий API, позволяющий добавлять контент, а не жёстко зашитый набор.
- **Совместные цели**: Epic Win или квест можно расшарить с друзьями и выполнять вместе, помимо чисто индивидуальных целей.
- **Рейтинги/лидерборды**: общий рейтинг + возможность собрать свой мини-рейтинг внутри маленького комьюнити (группы друзей).
- **Глубина RPG-механики — полная версия**, ближе к Habitica/SuperBetter, а не просто счётчик очков: персонаж/аватар, уровни и опыт (XP), "здоровье" персонажа, препятствия/боссы (аналог "плохих парней" из SuperBetter).

## 2. Платформы

- **iOS, Android и Web разрабатываются параллельно с самого старта** (не поэтапно) — Expo делает веб почти бесплатным поверх мобильного кода, поэтому решили не откладывать.
- Один общий backend + одна общая база данных — все клиенты (iOS/Android/Web) обращаются к одному и тому же API/БД, а не хранят данные локально независимо.

## 3. Дизайн

- Направление: **необрутализм (neo-brutalism)** — жирная типографика, высокий контраст, толстые обводки, яркие плоские цвета, крупные "грубые" UI-элементы. Хорошо сочетается с игровой/геймифицированной подачей.
- Архитектура дизайна должна закладывать возможность **выбора темы/оформления пользователем** — в первой версии одна тема (необрутализм), дальше — несколько на выбор (дизайн-токены, а не хардкод стилей).

## 4. Технологический стек

| Слой | Выбор | Статус |
|---|---|---|
| Backend | Node.js + TypeScript | ✅ подтверждено ранее |
| БД | PostgreSQL, общая для всех клиентов | ✅ подтверждено ранее |
| Мобильный клиент | React Native (Expo) — один код на iOS/Android | ✅ подтверждено |
| Веб-клиент | Expo Web / react-native-web — переиспользует тот же код | ✅ подтверждено, запускается параллельно с мобильными |
| ИИ-провайдер | Не используется в v1. Backend закладывает интерфейс `AICoachService`, чтобы подключить позже без переписывания фич | ✅ решено (отложено осознанно) |
| Авторизация | Email/пароль + Apple Sign-In + Google Sign-In, self-hosted на своём backend (без Firebase/Supabase) поверх общего Postgres | ✅ решено |

**Почему React Native (Expo), а не React (Vite/Next.js) + отдельные iOS/Android:** ранее для веба обсуждался React — но теперь приоритет iOS/Android с заделом под веб. Expo даёт один TypeScript-код на все три платформы (совпадает с принципом «один язык на всём проекте») и веб почти бесплатно поверх мобильной версии. Альтернатива — Flutter (тоже кросс-платформенный, включая веб, но другой язык — Dart, что противоречит «один язык»).

## 5. Ориентиры по геймификации (исследование)

Изученные приложения-аналоги — детали и источники в чате. Коротко:

- **SuperBetter** — понравился больше всего. Науч. обоснование (Univ. of Pennsylvania), фокус на психологической устойчивости, «квесты» и «плохие парни» (препятствия). Минус — заточен под конкретные челленджи (тревожность, выздоровление), не под ежедневные привычки в чистом виде.
- **Habitica** — самая глубокая RPG-механика (аватар, пати, групповая ответственность), open source. Минус — может быть избыточно сложной для «попроще».
- **Finch** — мягкая геймификация (виртуальная птица), фокус на self-care, а не RPG. Хорошо для не-хардкорной аудитории.
- **Fabulous** — упор на поведенческую науку и построение цепочек привычек, не RPG.
- **EpicWin** — простой геймифицированный to-do с анимированными «битвами» за задачи.

## 6. Авторизация — детали решения

Email/пароль + Apple Sign-In + Google Sign-In, всё на своём backend (Node.js + TS) поверх общего Postgres — без Firebase/Supabase, чтобы не плодить внешние зависимости и не выходить за рамки "один backend, одна БД".

**Почему так дешевле и без запар:**
- Свой сервер = не платим за MAU сторонним auth-провайдерам, только хостинг backend (который и так нужен).
- Apple Sign-In — **не опционально**: если в приложении есть вход через Google (или любой другой соц-логин), Apple по правилам App Store требует предложить и Sign in with Apple, иначе отклонят при ревью. Поэтому делаем оба входа сразу, не откладываем Apple "на потом".
- Реализация — стандартный, хорошо изученный паттерн (email/пароль с хешированием + OAuth-обмен токенами с Apple/Google), не что-то экзотическое — будет предложена конкретная библиотека на этапе кода auth-модуля.

## 7. AI-коуч — отложено, но заложено на будущее

В v1 ИИ не нужен. Backend с самого начала закладывает интерфейс `AICoachService` (анализ прогресса/действий пользователя, чтение базы проверенных источников по привычкам/позитивной психологии, выдача советов) — так, чтобы позже подключить провайдера заменой одной реализации, а не переписыванием фич.

По-настоящему бесплатного production LLM API не существует, но когда фича понадобится — кандидаты:

| Провайдер | Особенность |
|---|---|
| DeepSeek API | Заметно дешевле Claude/OpenAI, OpenAI-совместимый интерфейс — но платный, не бесплатный |
| Google Gemini API | Есть реальный бесплатный тариф с лимитами по запросам/токенам в минуту — подходит для прототипа |
| Groq API | Бесплатный доступ к открытым моделям (Llama и др.) с щедрыми лимитами, очень быстрый инференс |
| Claude API | См. `docs/claude-api-reference.md` — если важнее качество ответов, чем цена |

## 8. Статус

Архитектурные решения приняты и реализованы:
- Монорепо (backend + Expo-клиент + общие типы), регистрация/вход с «неограниченной сессией», dev-пользователь admin/admin
- Геймификация: персонаж (уровень/XP/HP), Epic Win → квесты → ежедневные задачи, стрики, совместные Epic Win (приглашение по email)
- Apple Sign-In (iOS) / Google Sign-In — код готов, но требует твоих собственных credentials из Apple Developer / Google Cloud, без них просто отвечает "не настроено" (см. README)
- Друзья (запросы/принятие) + лидерборд (общий и «я + друзья»)
- Таймлайн: дедлайны у Epic Win/квеста + экран со всеми квестами по датам
- `AICoachService`: интерфейс реализован, текущая реализация — правило-ориентированная заглушка без реального LLM (`RuleBasedAICoachService`), провайдера подключим позже одной заменой

Подробности, известные упрощения v1 и полный список API — в `README.md`.

Дальше: реальный AI-провайдер (см. раздел 7), мини-комьюнити как отдельная сущность (не просто «я + друзья»), drag & drop квестов, полноценное тестирование веб-сборки.
